## Asosiy qarorlar (advisor + spec)

1. **Pul string↔number chegarasi (#1 bug manbai).** Tranzaksiya puli (`totalAmount`, `paidAmount`, `discount`, `unitPrice`, `subtotal`) va `ServicePrice.price` — **string**. `StageBalance`/`PlanBalance` (`cost`/`paid`/`remaining`/`totalCost`/`totalPaid`/`balance`) — **number**. `tx→VM` mapper string'larni `Number(...)` qiladi; allocation/plan mantiq number'da ishlaydi. Mapper testi string kiritib numeric VM tekshiradi.
2. **Narx avto-to'ldirish — sof birlik + async wiring ajratilgan.**
   - Sof: `findActivePrice(prices: ServicePrice[], branchId: string): number | null` — `branchId` mos + `validTo === null` qatorni topadi (bir nechta bo'lsa eng oxirgi `validFrom`), `Number(price)`. Manba: `service.get(id).prices` (bulk endpoint QO'SHILMAYDI).
   - Async: savatga qo'shilganda `qc.fetchQuery(serviceKeys.detail(id))` (imperativ, bir martalik) → `findActivePrice` → `unitPrice`. Qo'lda override mumkin. Behavioral test `useServicePrice`/fetch hook'ni mock qilib savat qatori narxini tekshiradi.
3. **`patientId` CashierScreen'da yashaydi.** PosPanel (gap 3) va PlanBillingPanel (plan billing) ikkalasi ham tanlangan bemorga muhtoj. Selektor CashierScreen'da, pastga prop sifatida uzatiladi.
4. **Route eksport nomi o'zgarmaydi.** `App.tsx:17` `{ CashierPage }` import qiladi, `:72` route qiladi. `cashier.page.tsx` `CashierPage` eksport qilishni davom ettiradi (yupqa entry → `<CashierScreen/>`).
5. **i18n: mavjud gap ham bor.** `cashier.type` faqat `refund` ga ega; sahifa `payment`/`void` ham chaqiradi (hozir yo'q). Yangi kalitlar + yetishmayotgan `type.payment`/`type.void` ikkala (uz+ru) faylga, mavjudlar saqlanadi.
6. **Allocation payload (sof, tested).** `paidAmount = sum(amounts)`; har `amount ≤ stage.remaining` (qisman ruxsat). Builder: `{treatmentPlanId, allocations:[{stageId,amount}], paidAmount, paymentMethod}`. To'g'ridan test qilinadi.
7. **Erkin POS vs plan billing ajratish:** `SegmentedControl` (`payment` | `plan`) CashierScreen chap ustunida. CashierScreen smoke testi segment mavjudligini tekshiradi.
8. **Tech notes:** `zod4Resolver` (`mantine-form-zod-resolver`) — `zodResolver` Zod 4'da crash qiladi (ServiceFormModal'dagi `zodResolver` latent bug, KO'CHIRMAYMIZ). State-driven `<Modal>` refund (ModalsProvider yo'q). `@tabler/icons-react`. Mantine `Select` searchable/clearable (R0 Select bularsiz).

### Task 3 — mappers (ENG MUHIM, sof)
- **Test** `cashier.mappers.test.ts`:
  - `findActivePrice`: branch mos + `validTo===null` → `Number(price)`; mos yo'q → `null`; bir nechta active → eng oxirgi `validFrom`.
  - `computeNetTotal(cart, discount)`: `Σ unitPrice*qty − discount`; discount=0; manfiy bo'lmaydi (floor 0).
  - `buildCreatePayload({branchId, patientId, cart, discount, paidAmount, paymentMethod, notes})` → `{ branchId, patientId?, items:[{serviceId,serviceName,quantity,unitPrice}], discount, paidAmount, paymentMethod, notes? }`; `paidAmount` bo'sh → `netTotal`.
  - `buildAllocationPayload({treatmentPlanId, branchId, selections:[{stageId,amount}], paymentMethod})` → `{ branchId, treatmentPlanId, allocations, items:[], discount:0, paidAmount:Σamounts, paymentMethod }`.
  - `toTransactionVM(tx: CashierTransaction)`: string pul → number (`Number(totalAmount)` va h.k.).
  - `toPlanBalanceVM(b: PlanBalance)`: stage state: `remaining<=0`→paid; `paid>0`→partial; else unpaid.
- **Impl** `cashier.mappers.ts` (sof funksiyalar). `buildCreatePayload`/`buildAllocationPayload` `api.cashier.create` body tipiga mos.
- **Commit:** `feat(web): cashier.types + mappers (findActivePrice/netTotal/payloadlar/VM) + test`.

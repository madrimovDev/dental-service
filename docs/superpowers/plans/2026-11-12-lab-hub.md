# Lab Hub (laboratoriya portali) — Implementation Plan

> Ijro: `docs/ORCHESTRATION-GUIDE.md`. **Spec:** `docs/superpowers/specs/2026-11-12-lab-portal-design.md` (L1–L10). Kanvas: `LabPortal.dc.html`, `LabOrder.dc.html`. 2 to'lqin: **W1** (hub-core ∥ saas-sv) → merge → **W2** (hub-web ∥ clinic-sync).

**Goal:** laboratoriya o'z portalida bir nechta klinikadan kelgan ishlarni boshqaradi; klinika (SaaS va desktop) ishni chiquvchi so'rovlar bilan yuboradi va holat/narx/xabarlarni oladi; PHI saqlashda shifrlangan.

**Architecture:** yangi `apps/lab-hub-api` (Bun+Hono+zod-openapi+Drizzle, alohida Postgres bazasi `lab_hub`) va `apps/lab-hub-web` (Vite+React+Mantine, `@dental/ui`), `infra/lab-hub/` (compose+Caddy). Supervisor labs va klinikalarni yaratadi va Hub'ga ichki admin API orqali beradi. Klinika `apps/api` — outbox push + 60 s poll.

## Global Constraints
- Monorepo ichida, `@lab-hub/*` paket nomlari (Supervisor `@supervisor/*` naqshi). Stack CLAUDE.md §2 dan chetga chiqmaydi.
- **Shifrlash:** `apps/lab-hub-api/src/lib/crypto.ts` — konvert: lab uchun DEK (32 bayt, AES-256-GCM), `labs.dek_wrapped` = KEK bilan o'ralgan; KEK `LAB_HUB_KEK` (base64 32 bayt) env'dan, yo'q/noto'g'ri bo'lsa boot yiqiladi. Shifrlangan maydonlar `bytea`/`text` (`v1:<iv>:<tag>:<ct>` base64). Fayllar diskda `UPLOADS_DIR/<labId>/<uuid>.bin` faqat shifrlangan. Ochiq: status, muddat, id'lar, narxlar.
- **PHI chegarasi (L3):** Hub'ga faqat: bemor to'liq ismi, jinsi, yoshi, klinika kodi (bemor karta raqami emas — klinika ichki ish kodi), shifokor ismi, tishlar, ish turi, material, rang, muddat, izoh, fayllar. Telefon/manzil/pasport/tibbiy yozuv **yuborilmaydi** — klinika tomonidagi mapper testi bilan qulflanadi.
- Har lab — alohida ma'lumot doirasi: Hub'da RLS (`app.current_lab_id`) **yoki** har so'rovda servis darajasida `lab_id` filtri + test; tanlov: **RLS** (loyiha naqshi, `check:rls` Hub uchun ham).
- Supervisor → Hub ichki API: `Authorization: Bearer <SUPERVISOR_HUB_TOKEN>` (ikkala env'da, ≥32 bayt), faqat ichki tarmoq/HTTPS.
- Klinika → Hub: `Authorization: Bearer <clinic hub key>` (Hub'da SHA-256); kalit klinikada `tenant_settings` AES-256-GCM (Qaror #38).
- Obuna (L10): `labs.expires_at` + 7 kun imtiyoz, keyin lab portali va klinika so'rovlari shu labga 403 `lab.subscription_expired`; klinika obunasi (Supervisor) tugasa Hub klinikani rad etadi.
- Saqlash (L9): kunlik worker — `delivered_at < now() - 12 months` ishlarda ism/izoh/xabarlar `NULL`, fayllar o'chiriladi, `case_events`ga `purged`.
- i18n: Hub web uchun `packages/i18n` ichida `labHub.*` namespace (uz+ru); klinika tomoni `labHubClinic.*`.

## Review Focus
1. Bir lab boshqa labning ishlari/fayllarini ko'ra olmaydi; ulanmagan klinika labga ish yubora olmaydi.
2. Bazada va diskda bemor ismi/fayl ochiq holda yo'q (raw SQL va `cat` bilan tekshiriladi); KEK'siz boot yiqiladi.
3. Klinika internetsiz — ish navbatda qoladi, qaytganda bir marta ketadi (dublikat yo'q, `clinic_case_ref` idempotent).
4. Narx tasdiqlash ikki marta bosilsa — `expenses`da bitta yozuv.
5. Telefon/manzil hech qachon Hub so'roviga tushmaydi.

## W1 · Lane hub-core (T4, risky) — `apps/lab-hub-api` + Supervisor admin + infra
1. Skelet: `apps/lab-hub-api` (package.json, tsconfig, `src/app.ts`, `src/index.ts`, `src/db/{schema,client,migrate}.ts`, drizzle config), turbo/biome ro'yxatlari. Bazalar: `lab_hub` (dev), `lab_hub_test`.
2. Sxema (spec §2.2): `labs`, `lab_users` (role `lead|technician`, telefon `normalizePhone`, parol argon2/bun hash, `must_change_password`), `clinics` (`supervisor_clinic_id`, `mode desktop|saas`, nom, `hub_key_hash`, `expires_at`), `lab_clinic_links`, `price_list_items`, `cases`, `case_files`, `case_messages`, `case_events`, `settlements`. RLS lab_id bo'yicha.
3. `crypto.ts` + testlar (round-trip, noto'g'ri tag rad, KEK yo'q → throw).
4. Ichki admin API (Supervisor uchun): `POST /internal/labs` (lab + lead foydalanuvchi + vaqtinchalik parol), `PATCH /internal/labs/:id` (nom, katalogda ko'rinish, `expires_at`), `POST /internal/clinics` (upsert Supervisor klinikasi, `expires_at`) → `{ clinicId }`.
5. Klinika API (`/v1/clinic/*`, hub key bilan): `POST /v1/clinic/connect { supervisorClinicId, licenseKey?|serviceProof }` → Hub Supervisor ichki endpoint'i bilan tekshiradi → hub key (bir marta qaytariladi); `GET /v1/clinic/labs` (katalog), `POST /v1/clinic/links { labId }`, `GET /v1/clinic/links`; `PUT /v1/clinic/cases/:clinicCaseRef` (idempotent yaratish/yangilash, `sent` holatda), `POST .../files` (multipart, shifrlab saqlash), `POST .../messages`, `POST .../approve-price { price }`, `POST .../delivered`, `POST .../remake`; `GET /v1/clinic/changes?since=<cursor>` (holat/narx/xabar/fayl hodisalari, kursor = `"<tx_id>.<seq>"` — commit-xavfsiz, `apps/lab-hub-api/README.md`).
6. Lab API (`/v1/lab/*`, lab user JWT): login/change-password, cases list/filter (tab, texnik, muddat), case detail (deshifrlangan), assign, accept/reject(sabab)/in_progress/ready, propose price, messages, files (yuklab olish — deshifrlash oqimi), links (approve/reject), price list CRUD, settlements (klinika bo'yicha: jami `approved_price`, `paid` belgilash), users (lead texnik qo'shadi).
7. Saqlash worker'i (L9) va obuna gate'i (L10).
8. Supervisor (`apps/supervisor-api` + `apps/supervisor-admin`): «Laboratoriyalar» bo'limi — yaratish, uzaytirish, vaqtinchalik parolni bir marta ko'rsatish; Hub'ga ichki API chaqiruvi; `GET /internal/clinics/:id/verify` (Hub uchun: klinika faol/obuna muddati, desktop litsenziya kaliti mosligi).
9. `infra/lab-hub/` compose (api, postgres, caddy, `uploads` volume, `backup.sh` — `pg_dump` + shifrlangan fayllar, KEK zaxiraga qo'shilmaydi) + README.
10. Testlar: `apps/lab-hub-api/tests/*.test.ts` — crypto, RLS izolyatsiya (lab A ≠ lab B), ulanmagan klinika 403, idempotent PUT, changes kursori, narx tasdig'i, saqlash worker, obuna 403, bazada ochiq ism yo'q (raw SQL), KEK yo'q boot.

## W1 · Lane saas-sv (T3, risky) — SaaS tenantlar Supervisor'da (L8)
1. Supervisor `clinics.mode text NOT NULL DEFAULT 'desktop'` (`desktop|saas`), `saas_tenant_id uuid UNIQUE NULL`, `subscription_expires_at`; ichki `POST /internal/saas/clinics` (SaaS API xizmat kaliti `SUPERVISOR_SAAS_TOKEN` bilan) va `GET /internal/saas/clinics/:tenantId/status`.
2. `apps/api` (SaaS rejimi, `DENTAL_LOCAL_DESKTOP` emas): `register-tenant`dan keyin `onAfterCommit` bilan Supervisor'ga ro'yxat (best-effort + qayta urinish worker'i; `tenant_settings.supervisor_clinic_id`); kunlik holat sinxroni → `tenant_settings.subscription_expires_at`. Obuna muddati tugasa SaaS'da P18 bilan **bir xil** banner/blok (`requireValidLicenseInDesktop` naqshini rejimga bog'liq bo'lmagan `requireValidSubscription`ga umumlashtirish — desktop xulqi o'zgarmaydi). Yangi SaaS tenantga sinov muddati: 14 kun (Supervisor default).
3. Supervisor admin: klinikalar ro'yxatida rejim ustuni, SaaS klinikani uzaytirish (mavjud renew naqshi).
4. Testlar: supervisor `clinics.test.ts` kengaytmasi; `apps/api/tests/integration/l8-saas-supervisor.test.ts` (ro'yxat, Supervisor o'chiq — tenant yaratish baribir 201, keyin worker; muddat tugadi → 403; desktop rejimi o'zgarmagan — mavjud `cli-387`, `p18` testlari).

## W2 · Lane hub-web (T3) — `apps/lab-hub-web` (kanvas `LabPortal`)
Login (+ majburiy parol almashtirish), ishlar ro'yxati (Yangi/Ishda/Tayyor/Jo'natilgan, muddat chip'i, texnik filtri), ish detali (bemor, tishlar, fayllar ko'rish/yuklab olish, shifokor izohi, yozishma, texnik tanlash, narx taklifi prays-listdan, «Tayyor — jo'natishga», «Rad etish…»), klinikalar (so'rovlar, akt-sverka, to'landi belgisi), prays-list, xodimlar. Light+dark, uz/ru. Testlar: vitest komponent testlari + build; vizual kanvas bilan.

## W2 · Lane clinic-sync (T4, risky) — klinika `apps/api` + `apps/web`
1. Migratsiya (keyingi bo'sh raqam): `lab_orders.lab_hub_lab_id`, `lab_hub_case_ref` (unique), `hub_sync_status`, `proposed_price`, `approved_price`, `approved_at`; `lab_hub_outbox`; `lab_hub_state` (kursor, hub key shifrlangan).
2. Hub klienti `apps/api/src/lib/lab-hub/*`: connect (desktop — litsenziya kaliti; SaaS — `supervisor_clinic_id` + xizmat kaliti), outbox worker (backoff, idempotent), poll worker 60 s → `lab_orders` holat/narx/xabar yangilanadi + `notifications`.
3. **PHI mapper** `toHubCase(labOrder, patient)` — faqat L3 maydonlari; test: telefon/manzil yo'q.
4. Narx tasdig'i: `POST /api/lab-orders/{id}/approve-price` (`lab_order.manage`) → Hub + `expenses` (kategoriya «Laboratoriya», `lab_order_id` unique — ikkinchi bosish 409/no-op).
5. Web: Sozlamalar → «Laboratoriyalar» (katalog, ulanish so'rovi, holat); lab buyurtma sahifasi (labui lane qurgan) — katalogdan lab, «Laboratoriyaga yuborish», Hub holati/sinxron belgisi, narx taklifi + «Tasdiqlash», yozishma.
6. Testlar: `apps/api/tests/integration/lab-hub-sync.test.ts` (Hub — real `apps/lab-hub-api` app'i in-process yoki test serveri; offline navbat, dublikatsiz, poll holatni yangilaydi, narx ikki marta → bitta expense, PHI mapper), web `src/features/clinical src/features/settings`.

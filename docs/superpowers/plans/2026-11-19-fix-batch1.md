## Umumiy qoidalar (har lane)

1. Har FX uchun avval **failing test** (yiqilishini ko'r), keyin tuzatish, keyin yashil. Test fayl nomi: `apps/api/tests/integration/fx-NN-<qisqa>.test.ts` (web: komponent yonida `*.test.tsx`, vitest).
2. Pul/RLS/litsenziya/ruxsat bandlarida kamida bitta **real-DB** test (lane bazasi worktree `.env`da — buyruqqa URL qo'shma, `.env` yagona manba).
3. Testlar: `cd apps/api && bun test --env-file=../../.env --timeout 30000 <fayllar>`; web: `cd apps/web && bunx vitest run <fayllar>`. Argumentsiz test TAQIQ. Typecheck: tegilgan paketda `bunx tsc --noEmit -p <paket>`.
4. **Ruxsat/filial testlari real cheklangan rol bilan** (`@owner` emas).
5. 4xx'da yozuv saqlansa → `fail()`; tashqi side-effect → `onAfterCommit`.
6. **i18n:** yangi kalitlar `packages/i18n/src/locales/{uz,ru}.json` ikkalasiga; faqat o'z lane prefiksi ostidagi yangi kalitlar, mavjud kalitni o'chirma/qayta nomlama.
7. **API schema o'zgarsa** va web kerak bo'lsa: o'z worktree'ingda `bun run generate:contract` yurgizishga RUXSAT (integratsiyada controller qayta generatsiya qiladi). Generatsiya qilingan fayllarni qo'lda tahrirlama.
8. **Migratsiya raqamlari oldindan biriktirilgan** (quyida). `drizzle-kit generate --name <nom>` bilan; boshqa raqam chiqsa — fayl/jurnal/snapshot'ni biriktirilgan raqamga moslab nomla.
9. `apps/api/src/app.ts` — faqat **C** lane tegadi.
10. Commit'lar o'z branch'ingga (`wf/fx-<lane>`), har FX alohida commit, xabar `fix(FX-NN): …`. main'ga merge/push YO'Q.
11. Bajarib bo'lmagan / shubhali band → `notDone` (sabab bilan), soxta yashil yo'q.
